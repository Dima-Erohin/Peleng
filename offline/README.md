# offline/ — 3D-траектории объектов по видео нескольких камер (задача хакатона)

**Что делает.** Берёт папку с видео нескольких камер (известные положение и ориентация камер по кадрам — CSV из
Unreal) и для каждого объекта (по умолчанию: грузовик и дрон) восстанавливает 3D-координаты по кадрам:

```
детекция в каждой камере -> сопоставление между камерами -> триангуляция -> фильтр Калмана в 3D -> CSV
```

Обработка **строго причинная**: оценка кадра k использует только кадры 0..k (фон в вычитании фона — по прошлым
кадрам, фильтр только вперёд, никаких проходов назад и сглаживания по будущему). Это проверяется тестом
(`test_causality_truncation`: результат кадра k не меняется, если обрезать данные после k).

## Запуск

```bash
# venv с numpy, scipy, opencv-python, ultralytics (torch CPU), matplotlib
python offline/run.py --data <папка с mp4 и csv> --out <папка результатов>
```

Один запуск -> в `<out>/`:

| файл | что это |
|---|---|
| `truck.csv`, `drone.csv` | **результат** — в формате эталона: `Frame;Loc_X;Loc_Y;Loc_Z` (Unreal, см, разделитель `;`), все кадры |
| `truck_diag.csv`, `drone_diag.csv` | служебное: режим (`tri` ≥2 камер / `mono` 1 камера / `predict` 0 камер / `init` / `none` до первой оценки), число и номера камер, использованные детекции, σ фильтра (м), ошибка репроекции (px), скорость |
| `<объект>/plot_xyz.png`, `plot_top.png`, `plot_error.png` | графики: X/Y/Z от кадра (наша оценка против эталона), вид сверху, ошибка по кадрам и число камер |
| `<объект>/metrics.txt`, `metrics.json` | метрики против эталона (если эталон есть и объект с ним сравнивается) |
| `<объект>/detections_*.json` | кэш детекций (повторный прогон трекинга — секунды) |
| `run_info.json` | параметры запуска, версия git, время, SHA-256 выходных CSV — чтобы проверить, что результат получен этим скриптом |
| `viewer.json` | всё для фронтенда (камеры, траектории, эталон, детекции) — формат ниже |

Полезные ключи:

* `--objects truck,drone` — какие объекты (пресеты — `offline/presets.py`); `--objects-file objs.json` — свой список.
* `--set ОБЪЕКТ.поле=значение` — переопределить любое поле пресета, например
  `--set drone.detector=offline.detectors.drone:DroneDetector`, `--set drone.detections=/путь/dets.json`
  (готовые детекции из файла), `--set truck.tracker.accel_std=2`, `--set drone.tracker.object_size_m=0.4`.
* `--skip-missing` — пропустить объект, если его детектор ещё недоступен.
* `--max-frames N`, `--no-cache`, `--no-plots`, `--no-viewer`.
* Оценка отдельно: `python offline/evaluate.py --est out/truck.csv --truth <эталон.csv> --diag out/truck_diag.csv`.
* Экспорт для фронтенда отдельно: `python offline/export_viewer.py --data <данные> --run <out>`.
* Тесты: `python -m pytest offline/tests -q` (синтетика, ~25 с).

## Как устроено

**Данные (`ue_data.py`).** Парсер CSV устойчив к cp1251/utf-8, `;`/`,`, запятой как десятичному разделителю,
служебным ячейкам справа («Focal length;35», «матрица;23,76*13,365мм»), битым ячейкам Excel («авг.13» -> NaN ->
линейная интерполяция по кадрам), дубликатам строк. Строка CSV k = кадр видео k.

**Системы координат.** Вход и выход — Unreal: левая система, X вперёд, Y вправо, Z вверх, сантиметры.
Внутри — правая система в метрах: `(x, y, z) = (X, −Y, Z) / 100` (отражение Y), обратное преобразование
`world_to_ue` применяется при записи. Камера Unreal (проверено проекцией эталона на все 5 камер с точностью
до 1e-11 px): строки `M = FRotationMatrix(Pitch, Yaw, Roll)` — оси камеры, `u = 960 + f·d_y/d_x`,
`v = 540 − f·d_z/d_x`, `f = focal_mm / 23.76 · 1920`; в осях OpenCV `R = [M₁; −M₂; M₀]·diag(1,−1,1)`.
Используется `CameraModel` и геометрия из `backend/peleng/geometry.py`. Камера 5 поворачивается — модель
камеры строится на каждый кадр.

**Детекторы (`detect_base.py`, `basic_detectors.py`, `offline/detectors/`).** Общий интерфейс:
`detect(cam_id, frame_idx, image, camera_model) -> list[Detection(bbox, point_px, score, cls, source)]`,
вызовы строго по возрастанию кадров. Базовые:
* `bg` — вычитание фона: фон — экспоненциальное среднее прошлых кадров (кадр k сравнивается с фоном по
  кадрам < k). Для поворачивающейся камеры 5 фон переносится гомографией чистого поворота `H = K·R_k·R_{k−1}ᵀ·K⁻¹`.
* `yolo` — ultralytics YOLO11 (COCO, классы truck/car/bus) по кадру.
* `yolo+bg` — объединение (пятна, совпадающие с рамками YOLO, отбрасываются; у пятен пониженный вес).
* Подключаемые: любой класс `модуль:Класс` с тем же интерфейсом (детекторы грузовика с точкой «перёд кабины» и
  дрона — `offline/detectors/`, их описание там). `roi_refine.py` — опция: сильная YOLO в окне вокруг прогноза
  трекера (прогноз — по кадрам < k).

**Трекер (`tracker3d.py`).** Фильтр Калмана, состояние `[p, v]` в 3D (или `[p, v, a]`, `model="ca"`), шум —
случайное ускорение σₐ (по вертикали можно задать отдельно — для наземной машины меньше; для дрона —
полностью 3D, допускает зависание). На каждом кадре:
1. прогноз;
2. гейтинг: детекция каждой камеры сравнивается с проекцией прогноза (Махаланобис по `S = J·P·Jᵀ + R_px`);
3. ассоциация между камерами: гипотезы из пар камер (двухвидовая триангуляция, проверка ошибки репроекции),
   жадно добавляются остальные камеры; выбор — больше «весомых» камер (пятно фона весит меньше детекции сети),
   ближе к прогнозу;
4. обновление — **итерационный EKF прямо по пикселям** всех камер гипотезы (≥2 камер = триангуляция с учётом
   прогноза). **Одна камера:** EKF по одному пикселю уточняет положение поперёк луча, глубину держит модель
   движения + измерение дальности по размеру рамки `d ≈ f·H/h_px` (H выучивается для каждой камеры, пока объект
   виден ≥2 камерами, или задаётся априорно — `object_size_m`, для дрона); **ноль камер** — прогноз;
5. создание трека — по многокамерной гипотезе, а при заданном `object_size_m` — и по одной камере (точка на
   луче на дальности по размеру); перезахват, если устойчивая детекция несколько кадров подряд противоречит треку.

Выходная точка: центр (по умолчанию) или «перёд по курсу» (`anchor=front`): центр + L/2·(направление скорости),
длина L причинно оценивается робастным МНК по сторонам рамок (`DimsEstimator`) — для грузовика, у которого
эталонная точка — перёд кабины. Несколько объектов: каждый объект — свой детектор и трек; внутри объекта —
опция `multi` (несколько треков с исключительным распределением детекций).

## Формат `viewer.json` (для фронтенда)

```
{ format: "peleng-offline-viewer/2", fps, n_frames,
  coords: {ue: "...", three: "..."},
  cameras: [ { id, name, video, width, height, focal_mm, sensor_mm, fx_px, fy_px, cx_px, cy_px,
               fov_v_deg, fov_h_deg, static,
               ue: {loc_cm: [X,Y,Z], rot_deg: {pitch, yaw, roll}},          // Unreal, кадр 0
               three: {position: [x,y,z], quaternion: [x,y,z,w]},            // THREE.PerspectiveCamera
               per_frame?: {ue_yaw_deg[], ue_pitch_deg[], ue_roll_deg[], three_quaternion[]} } ], // только у подвижных (камера 5)
  objects: [ { name, csv,
               estimate: { ue_cm[k] = [X,Y,Z], three_m[k] = [x,y,z], mode[k], n_cams[k], cams[k] = [id...],
                           used_det[k] = [[i, j]...], sigma_m[k], speed_mps[k], err3d_m[k]? },
               truth?: { ue_cm[k], three_m[k] },
               detections: { fields: [x1,y1,x2,y2,u,v,score,cls,source], cams: [id...],
                             frames[k][i] = [[x1,y1,x2,y2,u,v,score,cls,source], ...] } } ],
  run: {argv, git, time_s} }
```

* Three.js: метры, Y вверх, `(x, y, z) = (X_ue, Z_ue, Y_ue) / 100` (правая система). Камеру ставить так:
  `cam.position.set(...position); cam.quaternion.set(...quaternion); cam.fov = fov_v_deg; cam.aspect = width/height`
  (камера смотрит вдоль своей −Z). Для камеры 5 на кадре k брать `per_frame.three_quaternion[k]`.
* `mode`: `tri` (≥2 камер), `mono` (1 камера), `mono_size_prior` (1 камера, глубина только по априорному размеру — допущение), `predict` (0 камер, прогноз), `init` (создание трека), `none`
  (до первой оценки). `detections.frames[k][i]` — детекции камеры `cams[i]` на кадре k (пиксели исходного кадра
  1920×1080); `used_det[k]` указывает, какие из них вошли в обновление.

## Результаты на тестовом наборе (5 камер, 1001 кадр)

### Грузовик (эталон `SM_AA_track` — перёд кабины), ошибка 3D в метрах

Пресет `truck`: детектор `offline.detectors.truck:TruckDetector`, центр рамки -> EKF (σₐ = 7 м/с² по горизонтали,
0.5 по вертикали), выход «перёд по курсу» (L оценивается по рамкам). Все кадры имеют оценку.

| | RMSE | медиана | p90 | макс |
|---|---|---|---|---|
| **все кадры** | **8.70** | 5.93 | 14.01 | 22.64 |
| обновление по ≥2 камерам (`tri`) | 4.74 | 3.57 | 7.93 | 11.41 |
| 1 камера (`mono`) | 12.01 | 9.60 | 20.45 | 22.64 |
| 0 камер (`predict`) | 11.57 | 10.50 | 16.25 | 18.59 |

По интервалам видимости (по сцене):

| кадры | кто видит грузовик | RMSE | медиана | макс |
|---|---|---|---|---|
| 0–158 | кам. 1 (+5 издалека), с 51 — 1+2 | 6.32 | 1.64 | 11.94 |
| 159–303 | только кам. 2 (вид сзади) | 10.68 | 9.47 | 18.59 |
| 304–718 | 2–3 камеры | 5.17 | 3.78 | 12.93 |
| 719–784 | фактически одна | 8.50 | 8.68 | 11.50 |
| 785–905 | 2 камеры | 7.72 | 6.24 | 12.80 |
| 906–1000 | фактически одна | 17.73 | 17.82 | 22.64 |

Систематика: вдоль курса −3.4 м (оценка «перёд» отстаёт: длина L оценивается неточно), по Z +0.35 м.

Что пробовали (тот же трекер, RMSE 3D по всем кадрам): детектор `yolo+bg` (yolo11n 640 + вычитание фона) —
22.6 м (много ложных пятен: тень, «след», деревья; yolo11n плохо видит далёкий/заслонённый грузовик);
`TruckDetector` с точкой «перёд кабины» от детектора (`point=detector`) — 19.0 м; `TruckDetector` + центр рамки +
`anchor=front` — 11.6 м (σₐ=3) -> 8.7 м (σₐ=7, σ_px шире). Модель «рамка = проекция параллелепипеда» в EKF
(`meas=box`) на реальных рамках неустойчива (размеры/курс путаются) — оставлена опцией. Выборочное обновление
фона и подавление теней в `bg` дали больше ложных пятен — выключены по умолчанию.
Верхняя граница трекера (идеальные рамки 21×2.6×4 м с реальной видимостью): RMSE ≈ 4.6 м.

### Дрон

Детектор `offline.detectors.drone:DroneTemplateDetector`. Дрон неподвижен и виден **только камерой 5** (кадры
0–~624); все камеры неподвижны по положению (камера 5 только поворачивается), поэтому параллакса нет и
триангулировать нечем. Оценка — луч камеры 5 × дальность по видимой **ширине** рамки при **допущении** о размере
дрона `object_size_m = 0.5` м (`--set drone.tracker.object_size_m=...`); такие кадры в `drone_diag.csv` и в
`viewer.json` помечены `mode = mono_size_prior`. После ухода из кадра — прогноз (`predict`, дрон стоит).
Направление на дрон определено точно (суб-пиксель), **дальность — допущение**: ошибка размера на x % даёт ошибку
дальности ≈ x % (≈ 11 м от камеры 5 при 0.5 м). σ в служебном файле для этих кадров не учитывает ошибку
допущения (она систематическая).

### Время (CPU, 4 ядра, машина делилась с другими задачами)

| этап | время |
|---|---|
| детекция грузовика `TruckDetector` (5 камер × 1001 кадр) | ≈ 49 мин (1.5–2.9 с/кадр) |
| детекция дрона `DroneTemplateDetector` | ≈ 16 мин (≈ 1 с/кадр) |
| `yolo+bg` (дешёвая альтернатива для грузовика) | ≈ 22 мин |
| трекинг + запись + графики (на кэше детекций) | ≈ 20 с на объект |

Повторный прогон с кэшем детекций — секунды.

### Тесты (`offline/tests/test_offline.py`, синтетика по модели камер Unreal)

Системы координат и проекция; парсер CSV; точная триангуляция; ≥2 камер — RMSE < 1.5 м; интервал одной
камеры (EKF по лучу + дальность по размеру); **причинность** (обрезка данных после k не меняет кадры ≤ k);
отбрасывание ложных детекций; модели cv/ca; модель параллелепипеда; синтетический дрон (подъём, зависание,
пролёт, разрыв без камер, перезахват по одной камере); неподвижный объект в одной камере с априорным размером.

# offline/detectors — детекторы грузовика и дрона

Интерфейс — `offline/detect_base.py` (`detect(cam_id, frame_idx, image, camera_model) -> list[Detection]`, причинно).
Метки: `cls="truck"` / `cls="drone"`. Запуск как внешний детектор: `offline.detectors.truck:TruckDetector`,
`offline.detectors.drone:DroneTemplateDetector`, `offline.detectors.trained:TrainedDrone`.
Веса моделей в репозиторий не кладутся (ultralytics скачивает сам; `assets/drone_patch.png` — шаблон дрона 78x42, 7 КБ).

Данные: 5 камер 1920x1080, 30 к/с, 1001 кадр. Камеры 1–4 статичные, камера 5 стоит до кадра ~565, потом вращается по yaw.
Все числа ниже получены на тестовых видео; эталон грузовика — `SM_AA_track.csv` (проекция моделью Unreal), эталона дрона нет —
положение дрона проверено по самому изображению и по геометрии (см. ниже).

### Обучение (синтетика с аугментацией)
1. `python -I offline/detectors/drone_synth.py --data <папка с mp4> --out <датасет> --n-train 4000 --n-val 400`
   (патч дрона из усреднённых кадров камеры 5 + альфа; фоны — окна из кадров всех 5 видео, область реального дрона исключена;
   масштаб ширины 8–120 px лог-равномерно, поворот ±35°, отражение, яркость/тон, размытие движения и гауссово, шум, JPEG q35–95,
   полупрозрачность, 1–2 дрона на картинку, 15 % негативов; val-фоны не пересекаются с train).
2. `python -I offline/detectors/train_drone.py --data <датасет>/data.yaml --device cpu|mps|0 --epochs 30 --time 3 --out runs`
   (Mac M-серии: `--device mps`, `--workers 0` если ругается; веса yolo11n.pt скачаются сами). Результат: `runs/drone/weights/best.pt`.
3. Использование: `DRONE_WEIGHTS=.../best.pt`, детектор `offline.detectors.trained:TrainedDrone` (imgsz 1920).
Оценка времени на 4-ядерном CPU (машина общая): ~5–8 с/итерацию (batch 16, 640 px) → ≈20–30 мин/эпоха при 4000 картинок.
Для ночи: `--time 8` или меньше картинок (`--fraction 0.5`). На M-серии ожидается в разы быстрее.

Далёкий грузовик (кам. 2–4, 40–60 px, вид сзади/спереди-сверху) и перекрытый деревьями — слабое место всех COCO-детекторов.

Главный вывод: **эталонная точка — перёд кабины, а не центр рамки**: центр рамки отстоит на 44–290 px, оценка «самая передняя точка
маски в направлении движения минус 0.034·ширины» — на 8–30 px. Направление движения v — из трека центра рамки по прошлым кадрам
с компенсацией поворота камеры (для кам. 5 без компенсации ошибка 550 px — видимое смещение определяется вращением камеры).
Поправка kappa=0.034 подобрана по эталону (одна константа); остаточный систематический сдвиг по камерам: кам.1 ≈0, кам.3 ≈0.04·w,
кам.4 ≈0.08·w, кам.2 ≈0.17·w вдоль движения (камеры 2/4 смотрят на грузовик почти сзади — точка кабины скрыта прицепом).
Что дальше улучшить (не сделано): сегментатор плохо видит грузовик сзади и далеко — дообучить yolo11-seg на псевдо-метках от движения
(не по эталону, чтобы не подгонять); для кам. 2–4 использовать «монотонное» удержание (coasting) по треку, когда сегментатор молчит.
Возвращаются все кандидаты; главный помечен `extra["main"]=True` (берите его / максимальный score — второстепенные — части кузова).

## 3. Движение (общее)
Оценка на грузовике, «попал» = эталон внутри пятна ±15 px (все кадры, где эталон в кадре; часть — грузовик скрыт):
MOG2 / медиана 10 кадров / разность 3 кадров: кам.1 128/128 для всех; кам.2 435/434/434 из 814; кам.3 434/366/331 из 559;
кам.4 522/520/505 из 810; 0.4–3 ложных пятен на кадр. Рамки по движению грубые (включают тень/часть фона), поэтому
для точной локализации используется сегментатор на кропе. Для статичного дрона движение бесполезно (он — фон).
Компенсация вращения камеры 5 проверена: остаточная разность после гомографии K·R_k·R_{k−1}ᵀ·K⁻¹ 2.6–4.5 против 8–16 без неё.

## 4. Детектор грузовика YOLO-pose (`truck_pose.py`) — обучается на эталоне, для новых видео/движущихся камер

Идея: финальный грузовик тот же, камеры могут двигаться → вычитание фона не годится. Обучаем YOLO-pose, который сразу даёт рамку и
**9 keypoints: pivot (эталонная точка, Loc из CSV) + 8 углов 3D-параллелепипеда кузова** (по ним на одной камере решается PnP — `pnp_pivot`
в `truck_pose.py`; на синтетическом тесте при шуме углов 3 px ошибка pivot 0.2–4.8 м в зависимости от дальности 64–441 м, при 8 px — до 21 м на 325 м:
PnP по предсказанным углам полезен вблизи, далеко — только как приблизительная оценка дальности).

Разметка (`truck_dataset.py`, автоматически): pivot и рамка — проекция траектории эталона и параллелепипеда
(передний торец на 0.3 м впереди pivot, длина 22.0 м, полуширина 1.4 м, высота 4.5 м, низ на 1.7 м ниже pivot, курс — из производной
траектории); габариты подобраны по сегментационным рамкам yolo11x-seg и проверены по наложению на кадры всех камер (длина 22 м
сходится; ширина/высота — оценочные ±0.3 м). Отбор: pivot в кадре и грузовик не скрыт целиком (пятно движения пересекает рамку);
частично закрытый грузовик остаётся. Всего 1126 кадров (шаг 2): кам.1 74, кам.2 243, кам.3 188, кам.4 245, кам.5 376.
Часть меток шумная (в паре кадров грузовик уже за горой — пятно движения совпало случайно).
Аугментации: офлайн — вставка листвы поверх грузовика (45 % кадров), размытие/движение, шум, JPEG, яркость/тон; онлайн (ultralytics) —
масштаб 0.3–1.7, поворот ±10°, перспектива, сдвиг, отражение (flip_idx меняет левую/правую грани), mosaic, mixup 0.1, HSV.

Файлы: `truck_dataset.py` (датасет), `train_truck_pose.py` (обучение, чекпойнт каждую эпоху, автопродолжение при повторном запуске),
`eval_truck_pose.py` (доля найденных, px-ошибка pivot), `truck_pose.py` (детектор: `offline.detectors.truck_pose:TruckPoseDetector`,
`weights=` или `TRUCK_WEIGHTS`; `extra["pivot"]`, `extra["kp"]` = 9×[x,y,conf], `extra["kp_conf"]`).

### Пакет для Windows (Python 3.12, CPU), одна команда
Нужно: Python 3.12 (`py -3.12 --version`), клон репозитория (ветка с `offline/`), папка с 5 mp4 и CSV (включая `object_transform_SM_AA_track.csv`).
```powershell
cd C:\path\to\Peleng
powershell -ExecutionPolicy Bypass -File offline\detectors\run_truck_train.ps1 -Data "D:\project2" -Out "D:\truck_train" -Epochs 40 -Imgsz 640 -Batch 8
```
Скрипт сам: создаёт venv в `<Out>\venv`, ставит CPU-torch + `requirements_truck.txt`, генерирует датасет в `<Out>\truck_ds` (≈15–30 мин, один раз),
обучает YOLO-pose (`--device cpu --workers 2`, чекпойнт каждую эпоху в `<Out>\runs\All\weights\last.pt`). **Если процесс оборвался — запустите ту же
команду: продолжит с последней эпохи.** Итог: `<Out>\RESULT\truck_pose_All.pt` — этот файл прислать. Оценка времени: на нашем 4-ядерном CPU ≈ 5 мин/эпоха при
imgsz 640, batch 8 для 750 кадров → для 1126 кадров ≈ 7 мин; i7-10210U примерно такой же или медленнее: 40 эпох ≈ 4–6 ч. Если нужно быстрее: `-Epochs 25`.
Память: batch 8 при 640 укладывается в 16 ГБ с запасом (около 3–4 ГБ).
Проверка качества (опционально, в том же venv): `python -I offline\detectors\eval_truck_pose.py --weights <pt> --list <Out>\truck_ds\lists\valAll.txt --imgsz 640`
(valAll — часть тех же камер, не отложенная — это лишь контроль). Эксперименты A/B (отложенная камера): `-Exp A` / `-Exp B`.

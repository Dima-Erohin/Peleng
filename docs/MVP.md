# MVP: минимальная система на том, что есть под рукой

## Цель MVP
Поставил 2+ камеры как получится → положил на пол листок с доской → нажал одну кнопку → видишь людей
в 3D (скелет, ID, траектория, скорость). Больше камер → выше точность, **без изменений в коде**.

## Что есть сейчас
| Где | Устройства |
|---|---|
| Дома у Димы | HP (Windows) со слабой вебкамерой, Redmi Note 14S, возможно iPhone 17 Pro Max (ненадолго), возможно iPhone брата |
| У Макса | iPhone 16 Pro (лидар), iPhone 15, iPhone 13, возможно iPhone 15 Pro |
| На хакатоне | всё вместе; Wi-Fi — раздача с Redmi (он может быть и камерой, и точкой доступа) |

## Что уже работает (ветка `dev-dima`, папка `backend/`)
* **Любая камера**: вебкамера ноутбука (OpenCV), любой телефон через браузер (страница `/cam`, ничего ставить не надо),
  приложения IP Webcam / DroidCam по URL.
* **Быстрая калибровка положения**: доска ChArUco на полу, кнопка «Калибровать положение по доске», около 1 секунды на все камеры сразу.
  Доска задаёт начало координат и пол.
* **Оптика**: по умолчанию берётся приблизительно по углу обзора. Точно: кнопка «Оптика: 15 кадров» (≈30 с на камеру, один раз,
  сохраняется по ID камеры в `data/calib/<id>.json`).
* **YOLO-pose** (yolo11n-pose) → 17 точек скелета в каждой камере.
* **Сопоставление между камерами** по эпиполярной геометрии → **триангуляция** скелета (с отбрасыванием плохих видов).
* **Одна камера** → координата на полу по допущению «ноги на полу» (режим `mono`).
* **Трекинг 3D**: фильтр Калмана + венгерский алгоритм → ID, сглаживание, скорость, прогноз при перекрытии.
* **3D-вьювер** (Three.js): камеры-пирамидки с живыми кадрами, скелеты, траектории, «комната точками», отметка + замер расстояния (клавиша M).
* **Расширения** (`backend/peleng/ext/`, подключаются сами): **объекты** (YOLO / метки ArUco), **траектории** (восстановление записи, сшивка,
  сглаживание, экспорт CSV/JSON), **точность** (σ точек, проверка по доске и рулетке, отчёт по камерам).
* **Запись/повтор** сессий (`.jsonl`), **демо-режим** без камер (для Макса и для проверки алгоритмов).
* Тесты на синтетике: `pytest backend/tests` — геометрия, калибровка, точность конвейера (медиана < 5 см на демо-сцене), расширения. На реальных телефонах пока не проверялось.

## Порядок работы

### Дома (Дима: HP + Redmi)
1. Установка — см. [README](../README.md).
2. Распечатать доску: `python scripts/make_board.py` (A4, печать 100 %). Измерить клетку линейкой → `config.json`.
3. Скопировать `config.example.json` → `config.json`.
4. `python run.py --webcam` (вебкамера ноутбука + телефоны; без флага — только телефоны) → на ноутбуке открыть `https://localhost:8443/`, на Redmi — `https://<IP ноутбука>:8443/cam`
   (принять предупреждение о сертификате, ввести ID `redmi`, «Старт»).
5. Один раз: «Оптика: 15 кадров» для каждой камеры — водить доску перед камерой близко, под разными углами, по всему кадру.
6. Положить доску на пол так, чтобы обе камеры её видели (галочка «показывать найденную доску на превью» помогает) →
   «Калибровать положение по доске». Ошибка < 1 px — хорошо.
7. Убрать доску, пройтись → в 3D появится человек. Отметка (M) → пройти по рулетке 2–3 м → сверить.

Расстановка дома: ноутбук и телефон «друг напротив друга» работают, но лучше **под углом 60–120°**
(например, соседние углы комнаты): точнее триангуляция и меньше перекрытий. Телефоны — на стопку книг/шкаф, выше 1.5 м, с наклоном вниз.

### На хакатоне (4 iPhone + Redmi)
1. Redmi раздаёт Wi-Fi, ноутбук и айфоны подключаются к нему.
2. Оптика айфонов откалибрована **заранее** (у Макса дома) — файлы `data/calib/<id>.json` берём с собой.
   ID камер на телефонах должны совпадать с теми, что были при калибровке (страница запоминает ID).
3. Телефоны ставим (штативы/держатели), доску на пол в центре → одна кнопка → готово. Минута на всё.
4. Если сдвинули телефон — снова положить доску и нажать кнопку (оптику переделывать не нужно).

### Ограничения, о которых надо помнить
* **Доска должна быть видна всем камерам одновременно.** Лист A4 надёжно читается примерно до 2–2.5 м (720p), A3 — до 3–3.5 м.
  Для большой комнаты: A3, или 1080p на телефоне, или доску на экране ноутбука/планшета (тогда измерить клетку на экране).
* **Фиксировать фокус/зум**: снимать 1x; на Android кнопка «Фикс. фокус»; на iPhone Safari этого не умеет — не трогать экран во время работы.
* **Синхронизация**: телефон пересчитывает свои часы в серверные по пингам; кадры с рассинхроном > 150 мс в триангуляцию не идут.
* **Кадры по команде**: телефоны не шлют поток, а снимают кадр по команде сервера («capture»), рассчитанной так,
  чтобы кадры приехали к концу текущей детекции. Все телефоны снимают почти одновременно, трафика ровно столько,
  сколько успеваем обработать. Вебкамера/IP Webcam идут потоком — из них берётся кадр, ближайший по времени.
* **Разрешение**: для трекинга телефон уменьшает кадр до `pipeline.track_width` (640) сам; при калибровке, поиске доски на
  превью и сканировании комнаты сервер просит полное разрешение (то, что выбрано на странице `/cam`).
  JPEG распаковывается только когда кадр реально нужен.
* **Производительность** (HP i7-10510U, CPU): YOLO 640 ≈ 60 мс на кадр, 3–4 камеры ≈ 180–220 мс → ≈ 5 к/с, задержка ≈ 250 мс.
  На Mac с M-чипом — `"device": "mps"`. Частота камеры на телефоне (30/60) на трафик не влияет — только на свежесть кадра.

## Где могут помочь LLM (через провайдера: DeepSeek, Claude, GPT…)
Точность триангуляции LLM не улучшат — это геометрия. Полезны они в «обвязке»:
* **Подписи к комнате**: VLM смотрит кадр камеры → список предметов с примерными bbox (стол, диван, дверь) →
  их нижние точки проецируем на пол → коробки мебели в 3D без RoomPlan.
* **Помощник по установке**: по кадрам камер и отчёту калибровки VLM подсказывает «камера 2 смотрит слишком вниз», «доска в тени», «телефоны стоят почти на одной линии».
* **Вопросы к записи** на естественном языке: «сколько раз человек 2 подходил к двери», «где люди стояли дольше всего» — LLM переводит в запрос к `.jsonl`.
* **Описание событий** для жюри/оператора: «человек 1 вошёл в 12:03, прошёл 7.4 м, средняя скорость 0.9 м/с».
* Модели «картинка → 3D-мир» (генеративные миры): пока дорого и плохо доступно; для проекта не нужны. Ближе к делу —
  монокулярные модели глубины (Depth Anything V2 metric, Apple Depth Pro): по одному кадру дают плотную глубину → «комната точками» гуще. Можно попробовать позже.

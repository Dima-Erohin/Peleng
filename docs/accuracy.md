# Точность

Расширение «Точность» (`backend/peleng/accuracy.py`, `backend/peleng/ext/accuracy.py`, `backend/web/ext/accuracy.js`)
даёт три независимые оценки точности и отчёт по камерам. Идея для жюри: **одна оценка — из теории (геометрия камер),
две — измерением (доска с известным размером клетки и рулетка)**. Если они сходятся, цифрам можно верить.

## Что меряется

### 1. Неопределённость точки — `pos_std_m` (в каждом кадре)
Для каждого человека/объекта, найденного по ≥ 2 камерам (`mode: "tri"`), сервер считает, насколько может «гулять»
его 3D-точка, если каждая камера ошибается в положении точки на σ пикселей (по умолчанию 2 px в кадре трекинга —
типичный шум YOLO-pose):

    Cov(X) = σ² · (Σᵢ Jᵢᵀ Jᵢ)⁻¹,    Jᵢ — якобиан проекции точки в камеру i (пиксели/метр, с дисторсией)

`pos_std_m = [σx, σy, σz]` — корни из диагонали, метры, 1σ. Что видно по этой цифре:
* третья камера уменьшает σ;
* две камеры, смотрящие почти с одной стороны (или строго напротив друг друга), дают большую σ по глубине;
* далёкий человек — больше σ (пиксель покрывает больше метров).

Чего эта оценка **не** знает: ошибок калибровки (сдвинули телефон, неточная оптика) и рассинхрона камер.
Поэтому нужны проверки 2 и 3.

Во вьювере: эллипс у ног человека с полуосями k·σx, k·σy (k = 1, 3 или 10 — переключатель «кольцо в 3D»;
при 1–2 см σ кольцо в масштабе 1:1 почти не видно, поэтому по умолчанию 3σ) и строка «σ по горизонтали» в блоке «Точность».

### 2. Проверка по доске (автоматически, без рулетки)
Доска ChArUco кладётся **в любое место** зоны (не обязательно туда, где калибровали), так, чтобы её видели ≥ 2 камеры.
Кнопка «Проверка по доске»:
1. телефоны на ~2 с переключаются в полное разрешение, на всех кадрах ищется доска; положение каждого угла усредняется (медиана по кадрам);
2. каждый угол, найденный ≥ 2 камерами, **триангулируется так же, как точки скелета** (а не через калибровку положения по этой доске);
3. расстояния между соседними углами сравниваются с размером клетки `board.square_m`.

Результат: ошибка в мм (медиана, максимум, RMS, смещение — «система растягивает/сжимает»), ошибка на всей длине доски,
отклонение углов от плоскости (мм), наклон доски к полу, ошибка репроекции и «ожидаемая» ошибка из геометрии
(при шуме углов 0.5 px). Это проверка **масштаба и согласованности калибровки камер** в этой части зоны.

### 3. Проверка по рулетке
1. Человек (или объект) встаёт в точку A → «Точка A»: положение усредняется за 1 с (`avg_s`).
2. Переходит в точку B → «Точка B» (по умолчанию тот же ID, что в A).
3. Рулеткой меряется расстояние A–B, вводится в поле «по рулетке, м» → «Сравнить».

Результат: расстояние по системе, ошибка в см и %, ожидаемая ошибка из σ. Для людей сравнивается расстояние **по полу**
(точки `floor`, рулетка на полу), для объектов — 3D-расстояние. Если человек двигался во время замера (разброс > 10 см) —
предупреждение. Все проверки (доска и рулетка) сохраняются в `data/accuracy.json`, последние видны в таблице.

### 4. Отчёт по камерам
«Отчёт по камерам» (обновляется и сам при изменении камер):
* по камерам: ошибка калибровки положения (`extrinsics_reproj_px`), тип и ошибка калибровки оптики (`intrinsics_rms`),
  расстояние до центра зоны, видна ли камере середина зоны;
* по парам камер: угол между лучами в центре зоны и σ этой пары. Важен угол `min(α, 180° − α)`:
  **< 20° — предупреждение «камеры почти на одной линии»** (и рядом стоящие, и стоящие строго напротив);
* σ в центре зоны по всем камерам, σ людей прямо сейчас, сводка проверок (медианы по доске и рулетке);
* предупреждения: ошибка калибровки > 1.5 px, оптика приблизительная, центр зоны вне кадра.

Центр зоны — центр комнаты (`room.board_offset_m`) на высоте 0.9 м или `accuracy.zone_center`.

## Как проводить проверку на хакатоне

Подготовка (1 мин): камеры откалиброваны, люди отслеживаются; рулетка и доска под рукой.

1. **Отчёт по камерам** — показать жюри: «каждая камера откалибрована с ошибкой < 1 px; углы между камерами 60–90°;
   теоретическая точность в центре зоны ±1–2 см по горизонтали».
2. **Проверка по доске** — положить доску в другой части зоны (например, в 1.5 м от места калибровки), нажать кнопку:
   «клетка 50 мм, система мерит её с ошибкой N мм; доска плоская с точностью N мм». Можно повторить в 2–3 местах — видно,
   как держится точность по зоне. (Доска должна читаться: A4 — до ~2–2.5 м от камеры, A3 — до ~3.5 м.)
3. **Рулетка** — растянуть рулетку на полу на 2–3 м. Участник встаёт на начало, «Точка A», стоит секунду; встаёт на конец,
   «Точка B», стоит секунду; ввести длину → «Сравнить»: «система: 2.47 м, рулетка: 2.50 м — ошибка 3 см (1.2 %)».
   Сделать 2–3 замера в разных направлениях — в таблице медиана.
4. Что говорить: «Оценка из геометрии камер (σ) и два независимых измерения (доска — миллиметры на малом масштабе,
   рулетка — сантиметры на метрах) сходятся. Ошибка растёт к краям зоны и при одной камере (там режим mono, по допущению
   «ноги на полу»), это видно по кольцу вокруг человека».

Советы: точка человека — центр таза (`pos`), а на полу — середина между лодыжками (`floor`), поэтому стоять ровно,
ноги вместе, точно над отметкой. Ошибка рулетки > 5 % — повод перекалибровать (сдвинули телефон?) и посмотреть
предупреждения в отчёте.

## Настройки (`config.json`, раздел `accuracy`)
| Ключ | По умолчанию | Что это |
|---|---|---|
| `sigma_px` | 2.0 | шум точки в кадре трекинга, px — для `pos_std_m` и отчёта |
| `board_sigma_px` | 0.5 | шум углов доски, px — для «ожидаемой» ошибки проверки по доске |
| `board_collect_s` | 1.5 | сколько секунд собирать кадры доски |
| `board_reproj_px` | 5.0 | порог ошибки репроекции угла доски |
| `avg_s` | 1.0 | усреднение положения для точек A/B, с |
| `buffer_s` | 10.0 | сколько секунд положений хранить для A/B |
| `zone_center` | null | центр зоны для отчёта `[x, y, z]`; null — центр комнаты на 0.9 м |

## REST
| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/accuracy/board` | проверка по доске (`{"cameras": [..]}` — опционально) |
| POST | `/api/accuracy/point/a`, `/point/b` | запомнить точку A/B (`{"kind": "person", "id": 3}` — опционально) |
| GET | `/api/accuracy/points` | текущие A и B |
| POST | `/api/accuracy/tape` | `{"measured_m": 2.5}` → `{system_m, err_cm, err_pct, expected_cm, horizontal}` |
| GET | `/api/accuracy/history` | история проверок (`data/accuracy.json`) |
| POST | `/api/accuracy/history/clear` | очистить историю |
| GET | `/api/accuracy/report` | отчёт: `cameras`, `pairs`, `zone_sigma_cm`, `live`, `checks`, `warnings` |

## Типичные цифры (демо-сцена: 3 камеры по углам комнаты 5×4 м, 960×540, σ = 2 px)
σ человека по горизонтали ≈ 1 см, по высоте ≈ 0.6 см; углы между парами камер 46–88°.
На синтетике: доска, нарисованная в кадры и найденная детектором, — ошибка клетки < 1 мм.

# Peleng — инструкция по использованию

Peleng определяет 3D-координаты людей и предметов по нескольким камерам (телефоны + при желании вебкамера ноутбука)
в реальном времени, показывает их в 3D, записывает сессии, восстанавливает траектории и меряет собственную точность.

Порядок работы в одну строку: **установить → распечатать доску → запустить сервер → открыть страницу камеры на телефонах →
откалибровать → ходить**.

Подробности по отдельным функциям — в [objects.md](objects.md), [trajectory.md](trajectory.md), [accuracy.md](accuracy.md),
формат данных для фронтенда — в [data-format.md](data-format.md).

---

## 1. Установка (один раз)

Нужен Python 3.10–3.12 (на 3.14 тоже работает, но torch предупреждает о несовместимости). Из корня репозитория:

```bash
cd backend
python -m venv .venv
```

Активировать окружение — Windows (PowerShell):
```bash
.venv\Scripts\activate
```
macOS / Linux:
```bash
source .venv/bin/activate
```

```bash
pip install -r requirements.txt
```

Для сборки интерфейса на React нужен Node.js 18 или новее:
```bash
cd ../frontend
npm ci
npm run build
cd ../backend
```

Проверка, что всё встало (должно быть `… passed`):
```bash
python -m pytest -q tests
```

Модель YOLO-pose (`yolo11n-pose.pt`, ~6 МБ) скачается сама при первом запуске с камерами; для режима объектов YOLO —
`yolo11n.pt` (~5 МБ), тоже сама. На хакатон лучше прийти с уже скачанными моделями (лежат в `backend/`).

## 2. Подготовка

### Доска для калибровки
```bash
python scripts/make_board.py          # A4, клетка 50 мм
python scripts/make_board.py --a3     # A3, клетка 70 мм — видно дальше
```
Файлы появятся в `data/`. **Печатать в масштабе 100 % («Фактический размер», не «Вписать»).**
После печати измерить линейкой сторону чёрной клетки. Если не ровно 50 мм (70 мм для A3) — вписать реальный размер в
`backend/config.json` → `board.square_m` (в метрах), а `board.marker_m` пересчитать в той же пропорции (≈ 0.74 от клетки).
Для A3 в конфиге должно стоять `"square_m": 0.07, "marker_m": 0.052`.
Наклеить на картон — доска должна быть плоской.

Сколько видно: A4 надёжно читается примерно до 2–2.5 м от камеры, A3 — до 3–3.5 м.

### Метки для объектов (если нужны)
```bash
python scripts/make_tags.py                          # метки 0..5, сторона 50 мм
python scripts/make_tags.py --ids 0-11 --size-mm 80  # крупнее — видно дальше
```
Тоже 100 %, вырезать с белым полем, наклеить ровно. Одна метка — один предмет.

### Конфигурация
```bash
copy config.example.json config.json      # Windows
cp config.example.json config.json        # macOS / Linux
```
`config.json` не попадает в git — у каждого свой. В нём указываются только отличия от значений по умолчанию
(все умолчания — в `backend/peleng/config.py`; см. раздел 11).

## 3. Запуск

Все команды — из `backend/` с активированным окружением.

После изменения интерфейса пересоберите frontend из `frontend/`: `cd ../frontend && npm run build`.

| Команда | Когда |
|---|---|
| `python run.py` | **основной режим**: камеры — телефоны через браузер |
| `python run.py --webcam` | то же + вебкамера ноутбука (домашние тесты); `--webcam 1` — вторая камера |
| `python run.py --demo` | без камер: виртуальная комната, 3 камеры, 2 человека — для проверки и для фронтенда |
| `python run.py --replay ../data/sessions/session_….jsonl` | проиграть записанную сессию |
| `python run.py --no-https` | без HTTPS (только для ноутбука: телефон без HTTPS камеру не отдаст) |
| `python run.py --port 9000` | другой порт (по умолчанию 8443) |

При запуске сервер печатает адреса:
```
Вьювер на ноутбуке:  https://localhost:8443/
С телефона (камера): https://192.168.x.x:8443/cam
```
Если адресов несколько — нужен тот, что из сети, к которой подключены телефоны (обычно `192.168.…`;
`100.64.…` — VPN, `172.…` — WSL/Docker).

Остановить сервер — `Ctrl+C`.

## 4. Вьювер на ноутбуке

Открыть `https://localhost:8443/` в обычном браузере (Chrome/Edge/Safari). Сертификат самоподписанный:
**«Дополнительно» → «Перейти на сайт»** (один раз).

По умолчанию открывается режим **«Траектории»** с грузовиком и данными Project 02.
Для камер и калибровки переключитесь на **«Live-камеры»**
или откройте `https://localhost:8443/?workspace=live`.
Загрузка CSV/SVG, управление воспроизведением и контракт для бэкенда описаны
в [trajectory-playback.md](trajectory-playback.md).

Что на экране в режиме **«Live-камеры»**:
* **3D-сцена** (мышь: вращать, колесо — зум, правая кнопка — сдвиг): сетка пола, оси, доска, камеры-пирамидки с живыми кадрами,
  люди (скелет, ID, след траектории), объекты, кольца точности.
* **Строка состояния** слева сверху: режим, частота обработки, задержка, рассинхрон камер, время YOLO, какие камеры участвуют в 3D,
  координаты людей.
* **Превью камер** снизу — с рамками и скелетами.
* **Панель справа**: «Калибровка», «Камеры», «Сцена», «Запись», затем блоки расширений «Точность», «Объекты», «Траектории», «Журнал».

## 5. Подключение телефонов

1. Телефон и ноутбук — **в одной Wi-Fi сети** (на хакатоне — раздача с одного телефона или свой роутер).
2. На телефоне открыть `https://<IP ноутбука>:8443/cam`, принять предупреждение о сертификате.
3. Ввести **ID камеры** (например `redmi`, `ip15`, `ip16pro`) — по нему сохраняется калибровка оптики, поэтому ID
   каждого телефона должен быть всегда одинаковым (страница его запоминает).
4. Разрешение — **полное разрешение камеры** (по умолчанию 1280×720; 1920×1080 — доска видна дальше при калибровке).
   Для трекинга телефон сам уменьшает кадры до 640 px по ширине, так что на трафик это почти не влияет.
5. «к/с камеры» — 30 или 60. Это частота съёмки, а не отправки: кадры отправляются, когда их просит сервер.
   60 — кадр свежее, телефон сильнее греется.
6. **«Старт»**, разрешить доступ к камере. Внизу строка: размер, сколько кадров в секунду уходит, RTT, «подключено».
7. На Android — кнопка **«Фикс. фокус»** (фиксирует фокус и экспозицию). На iPhone Safari этого не умеет —
   **не трогать экран** во время работы.
8. Экран телефона не гаснет, пока страница открыта. Не сворачивать браузер.

Если обновили код сервера — **перезагрузить страницу `/cam`** на телефонах.

Брандмауэр Windows при первом запуске спросит про доступ — разрешить для частных сетей.

## 6. Расстановка камер

Положение и наклон камер система находит сама по доске — угол соблюдать не нужно. Но от расстановки зависит точность:

* **Минимум 2 камеры видят каждую точку зоны.** Где человека видит одна камера — только примерная точка на полу (режим `mono`).
* **Угол между камерами 60–120°** (если смотреть сверху): например, соседние углы комнаты. Камеры рядом или строго напротив —
  глубина «плавает» (отчёт точности предупредит «камеры почти на одной линии»).
* **Высота 1.5–2.5 м, наклон вниз**: меньше перекрытий, доска на полу видна под нормальным углом.
* Снимать **основным объективом 1×**, телефон закрепить (штатив, держатель, стопка книг). **После калибровки камеры не двигать.**

## 7. Калибровка

### 7.1 Оптика — один раз на каждый телефон
Кнопка **«Оптика: 15 кадров»** у камеры в блоке «Камеры». Водить доску перед этой камерой близко (0.5–1 м),
под разными углами, по всему кадру — до «готово: ошибка N px». Около 30 с. Результат сохраняется в `data/calib/<ID>.json`
и подхватывается при следующих запусках, пока ID тот же.

Без этого шага оптика берётся приблизительно по углу обзора (поле «обзор°», по умолчанию 68°) — работает, но менее точно.
Оптику iPhone удобно откалибровать заранее дома и взять файлы `data/calib/*.json` с собой.

### 7.2 Положение камер — каждый раз после расстановки
1. Положить доску **на пол** так, чтобы её видели **все камеры одновременно** (галочка «показывать найденную доску на превью»
   подсвечивает найденные углы).
2. **«Калибровать положение по доске»** — около секунды на все камеры. В журнале у каждой камеры: ошибка (px), расстояние до доски.
   **Ошибка < 1 px — хорошо.**
3. Убрать доску.

Доска задаёт систему координат: начало — центр доски, Z вверх, пол — z = 0, X — вдоль длинной стороны доски.

Если какую-то камеру сдвинули — снова положить доску и нажать кнопку (оптику переделывать не нужно).
Кнопка «Сброс» у камеры забывает её положение (оптика остаётся).

### 7.3 Калибровка цепочкой — если доску на полу видят не все камеры
Большая комната или камеры смотрят навстречу друг другу (доска A4 читается до ~2–2.5 м, A3 — до ~3–3.5 м): блок
**«Калибровка цепочкой»** → «Начать» → снимок доски на полу (видна хотя бы одной камере) → снимки доски в руках, которую
одновременно видят ≥ 2 камеры, по всем парам соседних камер → «Применить». Панель подсказывает, между какими камерами
перенести доску. Подробно — [chain-calibration.md](chain-calibration.md).

## 8. Работа

* Пройдитесь — в 3D появится человек с ID, скелетом и следом. Полупрозрачный — прогноз (человека на мгновение не видно).
* **«Отметка (M)»** или клавиша **M** — запомнить, где сейчас стоит человек; справа сверху показывается расстояние от отметки.
* **«Сбросить траектории»** — стереть следы.
* **«Комната точками»** — облако точек комнаты по кадрам камер (нужно ≥ 2 откалиброванных камер); «Убрать точки».
* Галочки «кадры камер в 3D» и «скелеты» — что показывать.

## 9. Объекты (мяч, машинка, предмет с меткой)

Блок **«Объекты»** → режим:
* **выкл** — по умолчанию (не тратит процессор);
* **YOLO (классы COCO)** — 80 классов; в поле классов через запятую, например `sports ball, cup, bottle` (пусто — все, кроме людей).
  Модель загрузится в фоне при первом включении;
* **метки ArUco** — предметы с напечатанными метками (раздел 2). Самый точный режим. Метку 5 см на обычных кадрах трекинга
  видно примерно до 1–1.5 м — для комнаты печатать 8–10 см.

В 3D объект — сфера (YOLO) или куб (метка) с подписью «класс #ID» и следом. «Сбросить» — очистить треки объектов.
На ноутбуке без видеокарты режим yolo — вторая нейросеть на процессоре: частота обработки заметно упадёт.

## 10. Запись, восстановление траекторий, экспорт

1. **«● Записать сессию»** → действие → **«■ Остановить запись»**. Файл: `data/sessions/session_ДАТА_ВРЕМЯ.jsonl`
   (люди и объекты по кадрам).
2. Блок **«Траектории»**: выбрать запись (⟳ — обновить список), при желании поменять «пропуск ≤ … с» (по умолчанию 1.5)
   и «сетка … Гц» (30) → **«Восстановить»**.
3. В 3D — гладкие линии (белые участки — заполненные пропуски) поверх бледных сырых точек; таблица по трекам: длительность,
   путь, средняя и максимальная скорость, заполненные пропуски, σ.
4. Ссылки **«скачать CSV / JSON»** — восстановленные и сырые данные.

Что делает восстановление: склеивает обрывки одного трека (человек скрылся за шкафом и появился с новым ID),
сглаживает траекторию по всей записи (вперёд и назад), заполняет пропуски до 1.5 с.

Из командной строки:
```bash
python scripts/restore_session.py ../data/sessions/session_20261103_120000.jsonl --out ../data/export --raw
```

**Кадры камер.** Рядом с `.jsonl` пишется папка `session_ДАТА_ВРЕМЯ_frames/` (JPEG по камерам + `index.jsonl`): уменьшенные кадры,
по умолчанию ширина ≤ 480 px, качество 70, не чаще 5 к/с на камеру. Кодирует отдельный поток; если не успевает, лишние кадры
отбрасываются, конвейер не тормозит (нагрузка ≈ 2 мс процессора на сохранённый кадр, то есть ~3 % одного ядра на 3 камеры).
Место: на демо ≈ 3 МБ/мин на камеру; для реальной сцены оценка 5–10 МБ/мин на камеру (зависит от детализации), 3 камеры — до 30 МБ/мин.
Настройки в `config.json`: `{"recording": {"frames": {"enabled": true, "max_width": 480, "fps": 5, "quality": 70}}}`;
`"enabled": false` — не писать кадры. Папку можно удалить — запись `.jsonl` останется рабочей (без превью при replay).

Проиграть запись во вьювере: `python run.py --replay ../data/sessions/session_….jsonl` — **страховка для демо**,
если на месте подведёт Wi-Fi или свет. Если рядом лежит папка кадров, во вьювере видны превью камер и текстуры на пирамидках,
синхронные с проигрываемыми кадрами. Кнопки калибровки в replay не действуют (настоящая калибровка `data/calib` не затрагивается).

### Зоны, линии подсчёта, тепловая карта
Блок «Зоны и события» во вьювере: «Нарисовать зону» → два клика по полу в 3D (углы прямоугольника); «Нарисовать линию» → два клика (начало и конец, стрелка — направление A→B).
В ленте событий — «вошёл / вышел (пробыл N с) / пересёк A→B», счётчики «внутри / входов / среднее время» у каждой зоны, переключатель «тепловая карта на полу».
Кнопка «Анализировать» прогоняет записанную сессию через те же правила и даёт сводку и CSV. Зоны хранятся в `data/zones.json`. Подробно — [zones.md](zones.md).

## 11. Точность

Блок **«Точность»**:
* **Кольца** вокруг людей и объектов — оценка ошибки положения (σ) из геометрии камер; переключатель масштаба кольца (1σ / 3σ / ×10 / скрыть).
* **«Проверка по доске»** — положить доску в любое место зоны так, чтобы её видели ≥ 2 камеры → ошибка размера клетки в мм
  и отклонение от плоскости. Проверка без рулетки.
* **Рулетка**: встать в начало → **«Точка A»** (стоять секунду) → встать в конец → **«Точка B»** → ввести длину по рулетке, м →
  **«Сравнить»** → ошибка в см и %. Для людей сравнивается расстояние по полу — стоять ровно, ноги вместе.
* **Отчёт по камерам**: ошибки калибровки, углы между камерами, σ в центре зоны, предупреждения.
  История проверок — в `data/accuracy.json`.

Пошаговый сценарий для жюри — в [accuracy.md](accuracy.md#как-проводить-проверку-на-хакатоне).

## 12. Настройки `config.json`

Указывать только то, что меняете. Основное:

```jsonc
{
  "server":   { "host": "0.0.0.0", "port": 8443, "https": true },
  "cameras":  [],                       // камеры, которые сервер открывает сам (телефоны через /cam — не нужно)
                                        // { "id": "ipwebcam", "source": "http://192.168.1.23:8080/video", "hfov_deg": 65 }
  "board":    { "squares_x": 5, "squares_y": 4, "square_m": 0.05, "marker_m": 0.037, "dictionary": "DICT_4X4_50" },
  "pose":     { "model": "yolo11n-pose.pt", "imgsz": 640, "conf": 0.4, "device": null },
                                        // device: null — авто; "cpu", "mps" (Mac с M-чипом), "cuda:0"
  "pipeline": { "max_fps": 15,          // потолок частоты обработки — поднять, если YOLO успевает больше (Mac)
                "track_width": 640,     // ширина кадров трекинга с телефонов
                "max_skew_s": 0.15,     // кадры с большим рассинхроном не идут в 3D
                "capture_timeout_s": 0.3 },
  "room":     { "size_m": [5, 4, 2.7], "board_offset_m": [0, 0] },  // коробка комнаты в 3D и где в ней лежала доска
  "objects":    { "mode": "off", "classes": [], "tag_size_m": 0.05 },  // см. objects.md
  "trajectory": { "max_gap_s": 1.5, "rate_hz": 30 },                     // см. trajectory.md
  "accuracy":   { "sigma_px": 2.0 }                                       // см. accuracy.md
}
```

Производительность (замер на HP i7-10510U без видеокарты): YOLO-pose 640 ≈ 60 мс на кадр, 3–4 камеры ≈ 5 обработанных кадров/с,
задержка ≈ 250 мс. На Mac с M-чипом: `"pose": {"device": "mps"}` и `"pipeline": {"max_fps": 30}`.
Для скорости на слабом ноутбуке: `"pose": {"imgsz": 480}` (быстрее примерно в 1.7 раза, точность чуть ниже).

## 13. Чек-лист на хакатоне

До выезда:
- [ ] модели скачаны (`yolo11n-pose.pt`, при необходимости `yolo11n.pt`), тесты проходят;
- [ ] оптика всех телефонов откалибрована, `data/calib/*.json` с собой, ID телефонов записаны;
- [ ] доска (A3 на картоне) и метки распечатаны и проверены линейкой;
- [ ] штативы/держатели, повербанки, кабели, рулетка;
- [ ] записана запасная сессия для `--replay`.

На месте (≈ 5 минут):
1. Раздача Wi-Fi (или свой роутер), ноутбук и телефоны в одной сети.
2. `python run.py` → вьювер на ноутбуке.
3. Телефоны в углах, высоко, наклон вниз → на каждом `/cam` → тот же ID, что при калибровке оптики → «Старт».
4. Доска на пол в центр → «Калибровать положение по доске» → ошибки < 1 px → убрать доску.
5. «Отчёт по камерам» без предупреждений → пройтись → проверка по рулетке.
6. Для демонстрации: записать сессию → «Восстановить» → показать траектории, метрики, CSV.

| Симптом | Что делать |
|---|---|
| Браузер не открывает `https://…:8443` | принять сертификат: «Дополнительно» → «Перейти на сайт» |
| Телефон не открывает страницу | одна ли сеть; правильный IP (`192.168.…`); брандмауэр Windows — разрешить Python в частных сетях |
| «Браузер не даёт доступ к камере» | открывать именно по `https://`; разрешить камеру в настройках сайта |
| Камера телефона «пропадает» | экран погас или браузер свёрнут — держать страницу открытой; телефон на зарядке |
| Доска не находится | ближе (A4 ≤ 2.5 м), A3 или 1080p на телефоне, свет без бликов, доска плоская, печать 100 % |
| Ошибка калибровки > 1–2 px | откалибровать оптику («Оптика: 15 кадров»); проверить `square_m` по линейке |
| Человек «прыгает», большая σ | камеры почти на одной линии — переставить под углом 60–120°; добавить камеру |
| Человек только `mono` | его видит одна камера, или вторая не откалибрована, или большой рассинхрон (строка состояния) |
| Большой рассинхрон | Wi-Fi перегружен: меньше камер/свой роутер, `track_width` 480; телефоны на 60 к/с |
| Низкая частота обработки | YOLO на процессоре: `imgsz` 480, выключить режим объектов YOLO, сервер на Mac (`device: mps`) |
| Всё сдвинулось | толкнули камеру — доска на пол и «Калибровать положение по доске» |
| После обновления кода телефон работает странно | перезагрузить страницу `/cam` |

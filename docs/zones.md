# Зоны и события, тепловая карта

Расширение «Зоны и события»: прямоугольник на полу → «вошёл / вышел / пробыл N с», линия подсчёта (A→B / B→A), тепловая карта присутствия.
Работает для людей и объектов, вживую и по записанным сессиям. Код: `backend/peleng/zones.py` (логика), `backend/peleng/ext/zones.py` (хук и REST),
`backend/web/ext/zones.js` (интерфейс). Тесты: `backend/tests/test_zones.py`.

## Как пользоваться
1. Блок **«Зоны и события»** в правой панели. Имя можно ввести заранее (иначе «Зона N» / «Линия N»).
2. **«Нарисовать зону»** → два клика по полу в 3D — противоположные углы прямоугольника (при втором клике появляется превью; перетаскивание
   мыши по-прежнему вращает камеру, клик — задаёт точку; Esc или «Отмена» — выйти). Многоугольник — через REST (`points`).
3. **«Нарисовать линию»** → два клика: начало A и конец B отрезка. Стрелка на линии — направление **A→B**: пересечение слева направо
   относительно вектора A→B (если смотреть от A к B). Обратное — B→A.
4. В списке у зоны: сколько внутри сейчас / всего входов / среднее время пребывания; у линии — счётчики A→B и B→A. ✕ — удалить.
   Зона с людьми внутри подсвечивается, на ней подпись «Имя: N».
5. **Лента событий** («ID 2 вошёл в «Дверь»», «ID 1 пересёк «Проход» A→B», «вышел из …, пробыл 2.9 с»). CSV — ссылка под лентой.
6. **Тепловая карта** — переключатель «тепловая карта на полу»: время присутствия по клеткам (по умолчанию 0.2 м),
   градиент прозрачный → синий → жёлтый → красный (шкала — от максимума клетки, степень 0.6, чтобы редкие места были видны); обновляется раз в 1.5 с.
   «Сбросить карту» обнуляет накопленное, «Сбросить счётчики» — счётчики зон/линий и ленту.
7. **Анализ записи**: выбрать сессию → «Анализировать» (события, сводка «входов / Σ с / среднее», CSV); «Карта записи на пол» показывает
   тепловую карту записи вместо онлайновой. Анализ идёт по **текущим** зонам.

Слои на полу: покрытие z = 0.004 м, тепловая карта z = 0.006, зоны z = 0.008, линии z = 0.010; все прозрачные, не пишут в буфер глубины.

## Правила событий
Положение трека — `floor` (метры, Z вверх), ключ трека — `(kind, id)`, где `kind` = `person` или `kind` объекта; ID людей и объектов не пересекаются.

| Что | Правило |
|---|---|
| Расстояние до границы | со знаком: «+» внутри зоны, «−» снаружи (до ближайшей стороны многоугольника) |
| Гистерезис `hysteresis_m` = 0.15 м | ширина полосы вокруг границы: **вход** при d ≥ +0.075 м, **выход** при d ≤ −0.075 м; внутри полосы состояние не меняется. Шум ±5 см у границы дребезга не даёт |
| Выдержка `min_time_s` = 0.3 с | условие входа/выхода должно держаться непрерывно 0.3 с. **Время события — момент первого кадра выдержки**, поэтому `dwell_s` не искажается задержкой подтверждения (на вход и выход смещение одинаковое — для равномерного движения dwell ≈ истинному). Трек, пробывший внутри < 0.3 с, не считается |
| Прогноз (`predicted: true`) | трек сейчас не виден, позиция — экстраполяция фильтра. Такие кадры **вообще не участвуют**: вход по прогнозу не начинается, выход по прогнозу не подтверждается, таймер выдержки на них не идёт, в тепловую карту они не пишутся. Состояние «внутри» замораживается до ближайшего измерения |
| Пропавший трек | нет в `persons`/`objects` дольше `lost_after_s` = 1.0 с (живой трекер держит прогноз 1.5 с, после чего убирает трек) → `exit` из всех зон с `reason: "lost"`, время — последнее **измеренное** положение, `dwell_s` — до него |
| Сброс треков (перекалибровка) | `exit` с `reason: "reset"`; конец записи при анализе — `reason: "end"` |
| Линия | сторона = знак расстояния до прямой AB, учитывается с отступом h/2 = 7.5 см (шум у линии не считается). Смена стороны между соседними «уверенными» положениями = пересечение, если соединяющий их отрезок пересекает **отрезок** AB; пройти мимо концов нельзя засчитать. Время — интерполяция момента пересечения |
| Тепловая карта | к клетке под `floor` добавляется время шага (интервал между кадрами трека, ≤ `max_dt_s` = 0.5 с); у каждого трека своя доля, т. е. два человека в клетке дают двойное время |

Изменение геометрии зоны (или удаление) сбрасывает её счётчики и состояние «кто внутри»; переименование и смена цвета — нет.

## Формат
Поле `zones` в сообщении `frame` (WebSocket и строка записи `.jsonl`), см. [data-format.md](data-format.md):
```jsonc
"zones": {
  "inside": { "z1": [ { "kind": "person", "id": 2, "dwell_s": 3.4 } ] },
  "lines":  { "l1": { "a_to_b": 5, "b_to_a": 2 } },
  "events": [ { "n": 17, "type": "enter", "t": 1730455201.5, "kind": "person", "id": 2, "zone": "z1", "name": "Дверь", "pos": [1.3, 0.4] } ]
}
```
События:
* `enter` — `zone`, `name`, `pos`;
* `exit` — то же + `dwell_s`, `reason` (`null` | `lost` | `reset` | `end`);
* `line_cross` — `line`, `name`, `direction` (`A→B` | `B→A`), `pos`.

У всех: `n` — сквозной номер, `t` — время (часы сервера, с), `kind`, `id`. События лежат внутри `frame`, поэтому попадают в запись сессии автоматически.

Зоны хранятся в `data/zones.json` (`{"zones":[…], "lines":[…]}`):
`{"id":"z1","name":"Дверь","color":"#58a6ff","type":"rect|poly","points":[[x,y],…]}`, `{"id":"l1","name":…,"color":…,"a":[x,y],"b":[x,y]}`.
Журнал событий и счётчики — в памяти (до 2000 событий), после перезапуска сервера обнуляются.

## REST (`/api/zones/…`)
| Метод | Путь | Что делает |
|---|---|---|
| GET | `/` | зоны, линии, параметры |
| POST | `/zone` | создать зону: `{"rect":[x1,y1,x2,y2]}` или `{"points":[[x,y],…]}` (≥ 3 точек), `name`, `color` (`#rrggbb`) |
| PUT / DELETE | `/zone/{id}` | изменить (любые поля) / удалить |
| POST | `/line` | создать линию: `{"a":[x,y],"b":[x,y]}`, `name`, `color` |
| PUT / DELETE | `/line/{id}` | изменить / удалить |
| GET | `/events?limit=100&after=n` | журнал событий (в памяти), `after` — только новее номера `n` |
| GET | `/events.csv` | журнал в CSV: `n,t,type,kind,id,zone_or_line_id,name,direction,dwell_s,reason,x,y` |
| POST | `/reset` | обнулить счётчики и журнал |
| GET | `/stats` | сводка по зонам (сейчас внутри и кто, посещений, суммарное/среднее/максимальное время по завершённым выходам) и линиям |
| GET | `/heatmap` | тепловая карта онлайн: `origin` (угол клетки 0,0), `cell_m`, `nx`, `ny`, `values` (секунды, построчно: сначала строка с меньшим y), `max`, `total_s`, `bounds_from` (`room` \| `dynamic`) |
| POST | `/heatmap/reset` | сбросить карту |
| GET | `/sessions` | записи в `data/sessions` |
| GET | `/analyze?session=…&cell_m=…` | прогнать запись: `events` (до 5000), `events_total`, `summary` (зоны/линии), `heatmap`, `frames`, `duration_s` |
| GET | `/analyze.csv?session=…` | события анализа в CSV (все) |

Любое изменение зон рассылается во вьювер сообщением `{"type":"zones","zones":[…],"lines":[…]}`.

Границы карты: если задан `room.size_m` (в демо задаётся сам) — сетка по комнате (центр комнаты — минус `room.board_offset_m`, как в карте покрытия);
иначе сетка растёт по мере надобности, но не шире `max_extent_m` = 30 м вокруг начала координат. При анализе записи комната берётся из её `hello`.

## Настройки (`cfg["zones"]`, значения по умолчанию в `peleng/zones.py`)
`hysteresis_m` 0.15, `min_time_s` 0.3, `lost_after_s` 1.0, `cell_m` 0.2, `max_extent_m` 30, `max_dt_s` 0.5, `events_max` 2000.

## Ограничения
* Только пол (`floor`), высота не учитывается; зоны — в мировых координатах доски, при перекалибровке со сдвигом начала координат их надо перерисовать.
* Многоугольники рисуются только через REST; во вьювере — прямоугольники.
* Прямоугольник во вьювере всегда по осям мира (без поворота); повёрнутый — многоугольником через REST.
* Анализ записи использует текущие зоны, а не те, что были в момент записи.

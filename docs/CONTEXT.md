## 1. Задача хакатона (дословно)

> «Разработать программное решение, которое по видеопотокам с нескольких калиброванных камер определяет 3D-координаты движущегося объекта (объектов) в режиме реального времени и восстанавливает его траекторию во времени.»

Скорее всего, организаторы ничего не дадут — ни камер, ни оборудования. Камерами будут наши телефоны.

## 5. Факты про датчики глубины (уже выяснено)

- Лидар есть только в iPhone **Pro / Pro Max** (с 12 Pro). У обычных iPhone его нет; фронтальный TrueDepth (Face ID) работает только до ~1 м и смотрит на пользователя — для комнаты бесполезен.
- Лидар — это не одна точка «по прямой»: он светит сотнями лазерных точек и выдаёт **карту глубины ~256×192 при 60 к/с**. Неподвижный телефон видит расстояние сразу до многих объектов.
- Но дальность **~5 м**, точность заметно падает после 3–4 м. Поэтому идея «два телефона по диагонали комнаты измеряют расстояние лидаром» не работает как основа — не добьёт.
- **Вывод:** глубину основной системы получаем геометрически — **триангуляцией с нескольких калиброванных камер**. Это и есть то, что требует задача, работает на любом телефоне и на 5–8 м точнее лидара.

## 6. Решение: архитектура

```
4 телефона (камеры) ──Wi-Fi──▶ сервер (Python, на MacBook)
   │
   ├─ 1. Приём потоков + синхронизация кадров по времени
   ├─ 2. Детекция людей (YOLO-pose, ultralytics) + трекинг в каждой камере (ByteTrack)
   ├─ 3. Сопоставление между камерами (эпиполярная геометрия + венгерский алгоритм)
   ├─ 4. Триангуляция (DLT / cv2.triangulatePoints для N видов) + проверка ошибки репроекции
   ├─ 5. Фильтр Калмана в 3D → гладкая траектория, прогноз при перекрытии
   └─ 6. WebSocket ──▶ 3D-визуализация в браузере (Three.js)
```

Стек бэкенда: Python, OpenCV, ultralytics (YOLO), FastAPI + WebSocket.
Стек фронтенда: браузер, Three.js.

### 6.1 Получение видео с телефонов
- Быстрый вариант: приложение **DroidCam** (или аналог) — есть на iOS и Android, отдаёт поток, который читает OpenCV.
- Continuity Camera на Mac не подходит — только один iPhone за раз.
- Продвинутый вариант: своя веб-страница, которая берёт камеру в браузере телефона (getUserMedia) и шлёт по WebRTC. Не нужно ничего ставить, но нужен HTTPS (mkcert / самоподписанный сертификат).

### 6.2 Калибровка (критично для точности)
- **Внутренние параметры** (фокусное расстояние, дисторсия) — для каждой камеры отдельно (разные модели = разная оптика). Шахматная доска или ChArUco, `cv2.calibrateCamera`. Делается заранее, дома.
- **Внешние параметры** (положение камер в комнате) — ArUco-маркеры / ChArUco-доска на полу, видимая всеми камерами. Маркер задаёт начало мировых координат (например, угол комнаты).
- Обязательно: снимать **основным объективом 1x**, **зафиксировать фокус, зум и экспозицию**, отключить стабилизацию. Если автофокус «поплывёт» или телефон сдвинется — калибровку переделывать.

### 6.3 Синхронизация по времени (главный скрытый риск)
- Кадры с разных телефонов приходят с разной задержкой.
- Для идущего человека рассинхрон 30–50 мс ≈ ошибка ~5 см — терпимо; больше — точки «разъезжаются».
- Простой способ: метка времени при получении кадра + выбор ближайших кадров. Точнее: синхронизация по вспышке/хлопку в начале записи.

### 6.4 Какую точку человека отслеживаем
- YOLO-pose даёт ключевые точки тела. Для траектории — середина бёдер; для «следа на полу» — середина между стопами.
- Запасной режим: если человека видит только одна камера — используем допущение «ноги на полу» (гомография плоскости пола) и всё равно получаем координату на полу.

### 6.5 Расстановка камер
- **4 камеры в углах комнаты**, высота ~2–2.5 м, наклон вниз. Каждую точку видят минимум 2–3 камеры, меньше перекрытий мебелью.
- Например: iPhone 13, iPhone 15, Redmi, iPhone 16 Pro. 15 Pro — запасной / 5-я.
- Больше 4 потоков, скорее всего, не стоит (нагрузка на Wi-Fi и YOLO). Лучше 4 потока в ~640p, чем 5 в 1080p.

## 7. Упрощённая 3D-модель помещения

Цель: не детальная 3D-модель, а упрощённая сцена — коробка комнаты, мебель коробками (столы, стулья), точки, траектории. Её можно крутить мышью и проигрывать перемещение человека во времени.

### Основной способ: Apple RoomPlan (на iPhone 16 Pro)
- Проходишь с телефоном по комнате 1–2 минуты → получаешь стены, двери, окна и **мебель параметрическими коробками с категорией** (стол, стул, диван, шкаф и т. д.) с точными размерами и положением.
- Результат `CapturedRoom` поддерживает Codable → можно выгрузить прямо в **JSON** (у каждого объекта размеры + матрица трансформации) → в Three.js рисуется как обычные коробки.
- Нужно маленькое Swift-приложение: основа — официальный пример Apple для RoomPlan, сборка в Xcode на MacBook. Хватит бесплатного Apple ID (установка живёт 7 дней).
- Запасной вариант без своего кода: готовые приложения-сканеры с экспортом (но обычно там сетка, а не коробки).

### Совмещение модели комнаты с координатами камер
- Простой способ: отметить **3 общие точки** (например, углы комнаты на полу) в модели RoomPlan и в триангуляции камер → вычислить преобразование.
- Продвинутый: тот же ArUco-маркер на полу распознаётся ARKit при сканировании (поиск заданных изображений) → совмещение автоматическое.

### Альтернативы, если RoomPlan не сработает
1. Вручную: рулеткой измерить комнату и мебель, записать в JSON.
2. По кликам: кликнуть угол стола на двух камерах → триангуляция → поставить коробку.

## 8. Лидар в реальном времени — только бонус
- Pro в углу может давать карту глубины до ~5 м; если человек ближе — 3D-координата даже с одной камеры, можно уточнять триангуляцию.
- Требует своё iOS-приложение, передающее видео + глубину (ARKit sceneDepth). Это большой объём работы → «вау-фича», если останется время, не основа.

## 9. 3D-визуализация (фронтенд)
- Three.js: комната и мебель (из JSON RoomPlan), камеры в виде пирамидок, человек — точка/капсула с ID, линия траектории.
- **Ползунок времени / повтор записи**, тепловая карта, скорость.
- Панель с видео камер и рамками детекций.
- Данные приходят с бэкенда по WebSocket.

## 15. Обновление (2026-11-02): курс на минимальный MVP

**Реальность по железу сейчас.** Начинает разработку Дима, у него дома: HP (Windows, слабая вебкамера), Redmi Note 14S,
возможно iPhone 17 Pro Max и iPhone брата (ненадолго). Айфоны — у Макса, подключим позже.

**Решения:**
- На питче может не быть времени на долгую калибровку и сканирование комнаты → нужен софт, где камеру **поставил → быстро откалибровал → получил 3D**.
  Калибровка положения — одна кнопка по листу с доской ChArUco на полу. Калибровка оптики — заранее, дома, сохраняется по ID телефона.
- Камеры **не обязательно в углах под потолком** (крепить долго): ставим как получится — на шкаф, книги, штатив; лучше под углом 60–120° друг к другу.
- Чем больше камер подключено, тем выше точность — **без изменений в коде** (N видов в триангуляции).
- Wi-Fi: дома — свой роутер; на хакатоне — раздача с Redmi (он же может быть камерой).
- Телефоны подключаются **через браузер** (страница `/cam`, HTTPS с самоподписанным сертификатом) — ничего ставить не надо, работает и на iPhone, и на Android.
- «3D-комната» на старте — **точками** (облако особых точек с откалиброванных камер) + коробка комнаты по размерам. RoomPlan — позже, у Макса.
- Даже одна камера даёт координату на полу (допущение «ноги на полу»); 2+ камер — полный 3D-скелет.
- LLM: могут пригодиться в обвязке (подписи мебели по кадру, помощник установки, вопросы к записи), но не для точности. Генеративные «картинка → 3D-мир» — пока не наш путь.

**Сделано:** каркас бэкенда в `backend/` (ветка `dev-dima`) — приём камер, калибровка, YOLO-pose, триангуляция, трекинг, 3D-вьювер, запись/повтор, демо-режим.

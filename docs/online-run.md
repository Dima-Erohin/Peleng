# Онлайн-прогон: грузовик считается в момент показа видео

Пять видео Project 02 играют как живые камеры. Сервер в момент показа находит грузовик в кадрах
и шлёт каждую новую 3D-точку во фронтенд. На странице «Траектории» онлайн-след растёт за грузовиком
под идущее видео. Будущих точек нет, готовых CSV тоже нет. Эталон (Cargo Truck · 01) показан для сравнения.

## Запуск одной командой

Нужны Python 3.11–3.13 (на 3.14 тоже работает, но с предупреждениями torch) и Node.js 18+, чтобы один раз собрать фронтенд.
Видео в git нет — нужна папка с `Way1.FinalImage.CineCameraActor1..5.mp4` и `object_transform_*.csv`.

Windows:
```bash
powershell -ExecutionPolicy Bypass -File run_online.ps1 -Data "C:\Programming\project2"
```

macOS / Linux:
```bash
./run_online.sh /путь/к/project2
```

Первый запуск сам создаёт `backend/.venv`, ставит `backend/requirements.txt` и собирает фронтенд.
Затем он докачивает `yolo11s.pt` (19 МБ) в `models/` и открывает `http://localhost:8600/`.
Прогон стартует, когда открывается страница. Кнопка «Перезапустить» в блоке «Онлайн-прогон» запускает его с начала видео.

Параметры:
* `-Port` / `--port` — порт сервера.
* `-Device` / `--device` — устройство: `auto` (CUDA → MPS → CPU), `cpu`, `cuda:0`, `mps`.
* `-Rebuild` / `REBUILD=1` — пересобрать фронтенд после `git pull`.

Те же опции принимает и сам сервер:
```bash
python offline/online.py --data <папка> [--weights models/truck_pose_All.pt] [--roi-weights yolo11s.pt] [--roi-below 99] [--fallback roi|none] [--no-browser]
```

## Что происходит

1. **Камеры.** У каждой камеры свой поток. Кадр k «снимается» в момент `t0 + k/30` по реальным часам.
   Кадры проматываются без распаковки (`grab`, аппаратное декодирование, если есть). В картинку
   распаковывается только кадр, который запросил рабочий цикл, как у живой камеры, у которой
   забирают свежий кадр.
2. **Шаг.** Рабочий цикл просит у всех камер следующий кадр по часам и выполняет три действия:
   * прогоняет **наш детектор позы грузовика** `models/truck_pose_All.pt` по всем камерам одним вызовом сети.
     Это YOLO-pose с 9 точками, обучена `offline/detectors/run_truck_train.ps1`, mAP50 позы 0.93;
   * если поза в какой-то камере молчит, а трек уже есть, ищет **YOLO в окне вокруг прогноза** трекера
     (`yolo11s.pt`, все окна одним вызовом);
   * делает шаг **3D-трекера** (`offline/tracker3d.py`, настройки пресета `truck_fused`): триангуляция по 2+ камерам,
     фильтр Калмана, гейтинг выбросов.
3. **Пропуск кадров.** Кадры, пришедшие, пока сеть занята, пропускаются, как в живой системе. Точка шага
   посчитана только по кадрам ≤ k. Трекер учитывает реальный шаг по времени между обработанными кадрами.
4. **Отправка.** Каждая точка сразу уходит по WebSocket `/ws/online`. Фронтенд дорисовывает след.
   Между точками модель грузовика едет по последней скорости, видео синхронизировано с часами сервера.

## Скорость и точность (ноутбук HP i7-10510U, CPU, 5 камер 1920×1080)

| Окно вокруг прогноза | Точек в секунду | Шаг | RMSE 3D | Медиана |
|---|---|---|---|---|
| `yolo11m.pt` | 0.5 | 2.2 с | 2.9 м | 0.7 м |
| **`yolo11s.pt` (по умолчанию)** | 0.85 | 1.1–1.2 с | 2.0–2.7 м | 0.9–1.0 м |
| `yolo11n.pt` | 1.2 | 0.8 с | 8.5 м | 0.8 м |
| `yolo11s.pt`, `--roi-below 2` | 1.4 | 0.5 с | 5.2 м | 0.7 м |

Ошибка считается против эталона по тем кадрам, где пришла точка.
Сама детекция позы на 5 камерах занимает около 0.33 с, остальное — окна и декодирование видео.
Разброс между прогонами заметен: кадры, на которые попадает обработка, зависят от времени.
На GPU (`--device cuda:0`) или Mac с M-чипом (`--device mps`) точек в секунду будет в разы больше,
а с ними вырастет и точность. Пакетный прогон по всем кадрам (`offline/run.py`, пресет `truck_fused`) даёт RMSE около 4 м.

Поля точки WebSocket:
* `frame`, `t` (с от начала видео);
* `pos` (Unreal, см);
* `vel` (см/с);
* `mode` (`tri` / `mono` / `predict` / `init` / `none`);
* `n_cams`, `cams`;
* `sigma_m`;
* `proc_ms`, `detect_ms`;
* `lag_ms` — задержка от «съёмки» кадра до отправки;
* `dets` — рамки по камерам.

Первое сообщение `hello` несёт `t0`, `server_time` и уже посчитанные `points`. Подключившийся позже зритель видит весь прогон.

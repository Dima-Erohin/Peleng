# Отслеживание объектов

Расширение «Объекты» находит в кадрах не только людей, а и предметы (мяч, машинку, дрон, коробку с меткой),
считает их 3D-положение по нескольким камерам и ведёт траекторию. Результат — поле `objects` в сообщении `frame`
(формат — [data-format.md](data-format.md)); записывается в сессию вместе с людьми.

Файлы: `backend/peleng/objects.py` (детекторы, сопоставление, 3D, трекинг), `backend/peleng/ext/objects.py` (хук конвейера, REST),
`backend/web/ext/objects.js` (блок в панели и 3D), `backend/scripts/make_tags.py` (метки для печати), тесты — `backend/tests/test_objects.py`.

## Режимы

| Режим | Что ищет | Точка объекта | Сопоставление между камерами |
|---|---|---|---|
| `off` (по умолчанию) | ничего, CPU не тратится | — | — |
| `yolo` | 80 классов COCO моделью `yolo11n.pt` (по умолчанию все, кроме `person` — людей ведёт основной конвейер) | центр рамки | тот же класс + эпиполярное расстояние центров, венгерский алгоритм для каждой пары камер |
| `aruco` | метки ArUco словаря `DICT_5X5_100` (`DICT_4X4_50` занят доской калибровки) | центр метки (пересечение диагоналей) | по ID метки |

Режим `aruco` — самый точный (центр метки находится с субпиксельной точностью): удобен для демо и проверки точности.
Модель YOLO грузится в фоне при первом включении режима `yolo` (ultralytics скачает `yolo11n.pt` сам, ~5 МБ); пока она грузится, объектов нет.

**3D:** ≥ 2 камер — триангуляция с отбрасыванием худшего вида (`triangulate_robust`), `mode: "tri"`.
Одна камера — `mode: "mono"`:
* YOLO — объект стоит на полу: низ рамки пересекается с полом, высота центра — по лучу через центр рамки над этой точкой;
  для летящего объекта неверно (нужны 2 камеры);
* метка — `solvePnP` по известной стороне метки (`tag_size_m`): ошибка в основном по глубине, порядка 1–2 % расстояния.

**Трекинг:** фильтр Калмана из `tracking.py`, отдельный экземпляр на каждый класс (мяч не перепутается с чашкой);
ID — общий счётчик с людьми, не пересекаются. Ускорение в модели больше, чем у людей (`accel_std` 6 м/с²): предметы бросают.

## Как пользоваться

1. Откалибровать камеры как обычно (доска на полу).
2. В панели вьювера блок **«Объекты»**: выбрать режим; для YOLO — классы через запятую (подсказки по списку COCO),
   пусто — все, кроме `person`. Например `sports ball, cup, bottle`.
3. В 3D: сфера (YOLO) или куб (метка) цвета ID, подпись `класс #ID`, след траектории; полупрозрачный — прогноз (объект пропал из виду).
   Кнопка «Сбросить» — сбросить треки и следы.

REST (меняет настройки без перезапуска, не сохраняет их в `config.json`):

```
GET  /api/objects/                 -> {"mode", "classes", "all_classes", "detector", "count", "proc_ms", "tag_size_m", ...}
POST /api/objects/  {"mode": "yolo", "classes": ["sports ball", "cup"]}
POST /api/objects/  {"mode": "aruco", "tag_size_m": 0.05}
POST /api/objects/reset
```

Настройки по умолчанию — `backend/config.json`:

```json
"objects": { "mode": "off", "classes": [], "model": "yolo11n.pt", "imgsz": 640, "conf": 0.35,
             "tag_dictionary": "DICT_5X5_100", "tag_size_m": 0.05, "full_res": false,
             "epi_thresh_px": 25.0, "reproj_thresh_px": 15.0, "mono_fallback": true,
             "gate_m": 1.0, "max_age_s": 1.0, "min_hits": 2, "accel_std": 6.0 }
```

`full_res: true` — в режиме `aruco` телефоны шлют кадры в полном разрешении (мелкие метки видно дальше, но больше трафика).
При обычных кадрах трекинга (640 px) метку 5 см уверенно видно примерно до 1–1.5 м; дальше — печатать крупнее (8–10 см).

В демо-режиме (`python run.py --demo`) в кадрах объектов нет, поэтому при включённом режиме проецируются синтетические:
мяч прыгает по кругу, коробка с меткой 7 ездит, чашка стоит на столе.

## Печать меток

```
python scripts/make_tags.py                       # метки 0..5, сторона 50 мм, A4 -> data/tags_DICT_5X5_100_50mm_0-5.pdf/.png
python scripts/make_tags.py --ids 0-11 --size-mm 80
```

Печатать в масштабе **100 %** («Фактический размер», не «Вписать»), 300 dpi. Размер — сторона чёрного квадрата;
после печати измерьте его линейкой и впишите в `objects.tag_size_m` (нужно только для режима одной камеры).
Вырезать по пунктиру, оставив белое поле вокруг метки, и наклеить на объект ровно (метка должна быть плоской).
Одна метка — один объект: одинаковые ID на разных предметах сольются в один.

## Ограничения

* YOLO: точка — центр рамки, это центр видимого силуэта, а не геометрический центр; у крупных предметов (стул)
  с разных камер это разные точки — ошибка до половины размера объекта. Для мяча — единицы сантиметров.
* Два одинаковых предмета на одной эпиполярной линии могут перепутаться между камерами (как и у людей) — помогает третья камера.
* Время детекции YOLO добавляется к циклу конвейера (на CPU ~30–60 мс на кадр камеры).

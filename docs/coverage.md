# Карта покрытия

Помогает расставить камеры: показывает на полу, какие участки видят **≥ 2 камеры** (там работает триангуляция — точное 3D),
**1 камера** (только приблизительное положение по допущению «ноги на полу», `mode: "mono"`) и **0 камер** (мёртвые зоны),
и насколько точной будет триангуляция в каждой точке.

Код: сервер — `backend/peleng/coverage.py` (расчёт) и `backend/peleng/ext/coverage.py` (REST), вьювер — `backend/web/ext/coverage.js`,
тесты — `backend/tests/test_coverage.py`.

## Как пользоваться при расстановке

1. Поставьте телефоны, откалибруйте положение по доске («Положение по доске»).
2. Во вьювере, блок **«Покрытие»** → **«Показать покрытие»**. На полу появится карта:
   * **зелёный** — ≥ 2 камер; чем ярче и насыщеннее, тем меньше ожидаемая ошибка;
     блёкло-оливковый — камеры видят, но смотрят почти по одной линии или издалека (ошибка большая);
   * **оранжевый** — одна камера;
   * **тусклый красный** — ни одной.
3. Под кнопкой — сводка: площадь с ≥ 2 / 1 / 0 камерами, медианная ожидаемая ошибка σ по горизонтали, сколько м² «точных» (σ ≤ ~3 см),
   какую площадь видит каждая камера, предупреждения (камера ничего не видит, нет общей зоны и т. п.).
4. Передвиньте/поверните камеру, откалибруйте заново — карта пересчитается сама (по сообщению `cameras`), если она включена.
   Цель — зелёная зона там, где будут ходить люди, лучше яркая; камеры — с разных сторон (угол между лучами 60–120°).

Настройки во вьювере: шаг сетки (0.1–0.5 м) и высота плоскости: **таз 0.9 м** (по умолчанию — именно эта точка человека триангулируется),
**пол** или **голова 1.6 м**. У стены под камерой пол часто не виден, а таз — виден: смотрите на высоте, которая важна.

## Как считается

* **Видимость.** Точка видна камерой, если она перед камерой дальше `min_depth_m` (глубина по оси взгляда > 0.2 м),
  не дальше `max_range_m` (10 м — дальше человек слишком мелкий для детектора) и проецируется внутрь кадра с отступом
  `margin_frac` (3 % ширины/высоты: у самого края человек обрезан и скелет не находится). Учитывается дисторсия объектива.
  Видимость не зависит от разрешения: модель камеры из реестра может быть под любой размер кадра.
* **Качество** (клетки с ≥ 2 камерами) — ожидаемая ошибка положения по горизонтали **σ_h** (1σ, см), если каждая камера ошибается
  в положении точки на `sigma_px` пикселей (2 px). Формула та же, что у `pos_std_m` в расширении «Точность» ([accuracy.md](accuracy.md)):
  ковариация σ² · (Σ Jᵢᵀ Jᵢ)⁻¹, Jᵢ — якобиан проекции (здесь — без дисторсии, для всей сетки сразу).
  σ — в пикселях кадра трекинга (`pipeline.track_width`, 640): модели пересчитываются под эту ширину.
  Она растёт, когда камеры далеко или видят точку почти по одной линии. Число `quality` ∈ [0, 1] — σ_h в логарифмической шкале:
  1 при σ_h ≤ `good_cm` (1 см), 0 при σ_h ≥ `bad_cm` (10 см); 0.5 ≈ 3 см.
  Дополнительно — `angle_deg`: лучший «эффективный» угол между лучами пары камер (0° и 180° одинаково плохи, лучше всего 90°).
* Не учитываются: заслоняющие предметы и мебель, другие люди, ошибки калибровки, освещение.
* **Границы сетки:** если задан размер комнаты (`room.size_m`, `room.board_offset_m`) — по комнате (как коробка комнаты во вьювере);
  иначе — по тому, куда смотрят камеры (пересечение лучей из кадра с плоскостью, не дальше `max_range_m`) с запасом 0.3 м.
  Не больше 12 × 12 м (`max_extent_m`) и 40 000 клеток (`max_cells`; иначе шаг увеличивается).
* Только откалиброванные камеры (с положением `R, t`); некалиброванные не учитываются.

## REST

`GET /api/coverage?cell_m=0.2&height_m=0.9` (оба параметра необязательны):

```jsonc
{
  "ok": true,                     // false — нет откалиброванных камер (сетка всё равно есть, из нулей)
  "origin": [-2.5, -2.0],         // [x, y] угла клетки (0, 0) — с наименьшими x и y, м
  "cell_m": 0.2, "nx": 25, "ny": 20,
  "height_m": 0.9,                // высота плоскости
  "bounds_from": "room",          // room | cameras | default
  // массивы длины nx·ny по строкам: клетка (ix, iy) — индекс iy·nx + ix, её центр —
  // (origin[0] + (ix + 0.5)·cell_m, origin[1] + (iy + 0.5)·cell_m, height_m)
  "counts":     [0, 1, 2, 3, ...],       // сколько камер видят
  "quality":    [null, null, 0.84, ...], // 0..1, null при < 2 камерах
  "sigma_h_cm": [null, null, 1.3, ...],  // ожидаемая ошибка по горизонтали (1σ), см
  "angle_deg":  [null, null, 74.2, ...], // лучший эффективный угол между лучами пары камер
  "summary": {
    "area_m2": 20.0, "area_2plus_m2": 14.9, "area_1_m2": 4.6, "area_0_m2": 0.5, "pct_2plus": 74.6,
    "sigma_h_cm_median": 1.56, "sigma_h_cm_p90": 3.85,
    "area_good_m2": 12.2           // ≥ 2 камер и quality ≥ 0.5 (σ_h ≲ 3 см)
  },
  "cameras": [ { "id": "demo1", "center": [x, y, z], "size": [960, 540], "hfov_deg": 68.0, "area_m2": 15.1 } ],
  "warnings": [ "..." ],
  "params": { "min_depth_m": 0.2, "max_range_m": 10.0, "margin_frac": 0.03, "sigma_px": 2.0, "ref_width_px": 640, "good_cm": 1.0, "bad_cm": 10.0 }
}
```

Сервер карту сам не рассылает: вьювер запрашивает её по кнопке и при сообщении `cameras` (если изменились положения камер).

## Настройки (`config.json`, раздел `coverage`)

```jsonc
"coverage": {
  "cell_m": 0.2, "height_m": 0.9,      // значения по умолчанию для запроса
  "min_depth_m": 0.2, "max_range_m": 10.0, "margin_frac": 0.03,
  "sigma_px": 2.0,                     // шум детекции, px кадра шириной ref_width_px
  "ref_width_px": null,                // null — pipeline.track_width
  "good_cm": 1.0, "bad_cm": 10.0,      // шкала quality
  "max_extent_m": 12.0, "max_cells": 40000, "pad_m": 0.3
}
```
